# Производительность

## Поиск и запуск сетевых треков

SoundCloud отдаёт URL стандартной JPEG-обложки размером 500×500 в метаданных.
Плеер использует этот размер без проверки оригинала отдельным HEAD-запросом.
Раньше yt-dlp выполнял такую проверку для каждого результата, в том числе при
плоском поиске и загрузке библиотеки. Изменение применяется к отдельным экземплярам
экстракторов; авторизация, пагинация и получение треков остаются в yt-dlp.

Проверка на одинаковых искусственных данных с настоящим парсером yt-dlp:

| Операция | До | После |
| --- | ---: | ---: |
| Проверки оригинальных обложек для 50 результатов SoundCloud | 50 запросов | 0 |
| Получение ссылок на 6 доступных кодировок SoundCloud в режиме «Авто» | 6 запросов | 2 |

При запуске SoundCloud режимы «Авто» и «Экономия трафика» сначала запрашивают
AAC через прямую ссылку либо HLS. Если AAC отсутствует, используется полный
список форматов. «Высокое качество», «Совместимость» и восстановление оборванного
потока сразу получают все кодировки. YouTube сначала проверяется на прямое
аудио без загрузки HLS/DASH-манифестов; при отсутствии такого аудио выполняется
полный поиск. Прямой видеопоток не подменяет аудио из HLS. Ошибки сети и доступа
не запускают дополнительный поиск форматов.

В одном сетевом замере `scsearch10:ambient` с уже сохранённым публичным client_id
поиск 10 треков занял **2,043 с до изменения и 0,419 с после**. Проверок обложек
было соответственно 10 и 0. Среда: Linux, Python 3.12, yt-dlp 2026.10.21,
без cookies и воспроизведения. Это единичный замер, а не обещание скорости:
ответы сервисов, доступ к аудиосерверам и сеть пользователя влияют на результат.
Сетевой запуск YouTube в этой среде не проверен: прокси отклонил соединение.
Запасные форматы, авторизация и отмена проверяются в `StreamLoading` в тестах.

## Память списков и обложек

В библиотеке сохраняются данные всех полученных треков. Сложные строки с
кнопками и подписями создаются только для видимой области с запасом примерно
восемь строк с каждой стороны. При прокрутке далёкие строки освобождаются;
при возвращении восстанавливаются из актуальных данных. Строка с фокусом
клавиатуры остаётся доступной до смены фокуса.

Обложки уменьшаются при декодировании до 768 пикселей по длинной стороне.
Кэш этих изображений ограничен **32 МиБ**, кэш скруглённых миниатюр — **4 МиБ**.
Это пределы отдельных кэшей, а не всей памяти приложения. Отображаемые картинки,
аудиобуферы, данные треков и библиотеки Qt занимают дополнительную память.
Одинаковые миниатюры переиспользуются с учётом размера и плотности экрана.

## Измерение

Сравнение выполнено в отдельных процессах Python 3.12 / PyQt6 6.11, Linux,
`QT_QPA_PLATFORM=offscreen`. Измерялся текущий RSS через `/proc/self/status`.
Внешние сетевые запросы и воспроизведение отсутствовали; настройки временные.
Базовая версия — `f2fca7f`.

Сценарий: создать окно, заполнить YouTube-библиотеку 2500 искусственными
треками, добавить все страницы списка, прокрутить в конец и обработать
отложенное удаление Qt. Затем загрузить восемь PNG-обложек 2048×2048 из памяти.
Между этапами обрабатывались события Qt и запускалась сборка мусора Python.

| Состояние | До | После |
| --- | ---: | ---: |
| Окно после запуска, RSS | 119 МиБ | 122 МиБ |
| Полностью добавленный список из 2500 треков, RSS | 510 МиБ | 127 МиБ |
| Живые TrackRow в этом списке | 2500 | 15 |
| После восьми больших обложек, RSS | 638 МиБ | 162 МиБ |

Число живых строк зависит от высоты окна и положения прокрутки. Результаты
относятся к этому искусственному сценарию. В Windows EXE, при воспроизведении
и с реальными обложками значения будут отличаться; это не прогноз расхода
памяти на компьютере пользователя.

Функциональные проверки находятся в `tests/test_player.py`: прокрутка назад,
поиск, действия на восстановленных строках, лайки, синхронизация, пределы
кэшей и загрузка изображений. Команда запуска — в `tests/README.md`.

## Запуск с сохранённой очередью

Очередь также использует строки только возле видимой области. Все позиции,
включая дубликаты, остаются в данных и в лёгких элементах списка. Движок yt-dlp
импортируется при первой операции извлечения в рабочем потоке.

Сравнение с `593c409` в отдельных процессах Python 3.12 / PyQt6 6.11, Linux,
без воспроизведения и внешней сети: заранее записан JSON с 2500 треками YouTube,
уникальными идентификаторами позиций и контрольной записью последнего трека.
Измерялось создание `MusicPlayer()` до показа окна, без времени импорта модулей.

| Восстановление очереди | До | После |
| --- | ---: | ---: |
| Время создания окна | 3,231 с | 0,095 с |
| Созданные TrackRow очереди | 2500 | 24 |
| Позиции очереди в данных | 2500 | 2500 |

Это синтетический замер восстановления, а не время запуска Windows EXE.
Основная Windows-сборка теперь содержит EXE и `_internal` в одной папке:
она не распаковывает библиотеки во временный каталог при каждом запуске.
Однофайловая сборка остаётся доступна через `build_exe.bat single`.
Время холодного запуска на Windows зависит также от диска и антивируса;
оно в этой среде не измерялось.

## Пользовательский фон

Выбранная картинка читается один раз, с учётом EXIF-поворота, и уменьшается
до 2048 пикселей по длинной стороне. Эта копия сохраняется в каталоге данных;
оригинал остаётся без изменений. Файлы больше 40 МБ и изображения больше
36 мегапикселей не принимаются.

Для отрисовки используется одна готовая композиция фона с затемнением,
также не больше 2048 пикселей по длинной стороне. Наведение не запускает
повторное чтение или масштабирование фотографии. Изменение размера окна,
темы или затемнения пересоздаёт кэш. Размытие и анимация фона отсутствуют.
При отсутствии выбранного фона большой растровый кэш не создаётся.
