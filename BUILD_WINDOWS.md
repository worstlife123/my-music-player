# Сборка EXE для Windows

1. Установи **Python 3.13 или 3.12, 64-bit** с [python.org](https://www.python.org/downloads/windows/). При установке включи Python Launcher или добавление Python в PATH.
2. Положи `build_exe.bat` рядом с актуальным `player_aurora_smart_beautiful_fixed_ui_repaint.py`. Также поддерживается имя главного файла `player.py`. Рядом нужны папки `assets` (с `aurora.ico`) и `fonts` из репозитория.
3. Запусти `build_exe.bat` двойным щелчком и дождись **BUILD SUCCEEDED**. Для установки зависимостей нужен интернет; права администратора не требуются.
4. Готовый плеер: **`dist\AuroraMusicPlayer\AuroraMusicPlayer.exe`**.

Скрипт создаёт отдельное окружение `.build-venv`, устанавливает PyInstaller,
PyQt6, yt-dlp и ytmusicapi. Библиотеки Qt для воспроизведения звука
собирают штатные hooks PyInstaller. yt-dlp и ytmusicapi
включаются вместе с данными пакетов и динамически загружаемыми модулями.
Локальный сборщик проверяет импорты перед упаковкой и запускает
собранный EXE с `--smoke-test` до сообщения `BUILD SUCCEEDED`.
Папка `fonts` включается целиком: шрифт Inter с кириллицей и его лицензия
SIL OFL 1.1. Отдельная установка шрифта не требуется.
Иконка `assets\aurora.ico` включается в ресурс EXE через `--icon` и в данные
приложения через `--add-data`. Она содержит размеры 16–256 px; дополнительных
библиотек для её сборки не требуется. Для изменения исходной отрисовки см.
[assets/README.md](assets/README.md).
При повторной сборке окружение используется снова, зависимости обновляются.

По умолчанию создаётся папка с EXE без консольного окна и зависимостями в
`_internal`. Переноси или архивируй **всю папку `dist\AuroraMusicPlayer`**:
один EXE без `_internal` не запустится. Эта сборка не распаковывает библиотеки
при каждом открытии, что уменьшает задержку холодного запуска.
Для запуска Python не нужен.

Если нужен именно один файл, выполни `build_exe.bat single`:
получится `dist\AuroraMusicPlayer.exe`. Он распаковывает зависимости во временную
папку при каждом запуске и может открываться заметно дольше, особенно с проверкой
антивирусом. Параметры можно сочетать: `build_exe.bat single debug`.

Интернет по-прежнему нужен для онлайн-музыки, а подключение
аккаунтов на другом компьютере выполняется в настройках плеера. Cookies,
кэш лайков и пользовательские настройки скрипт в EXE не добавляет.

Если сборка завершилась ошибкой, окно останется открытым: сохрани текст ошибки.
Если собранный плеер закрывается при запуске, открой CMD в папке проекта и выполни:

```bat
build_exe.bat debug
```

Затем запусти `dist\AuroraMusicPlayer-debug\AuroraMusicPlayer-debug.exe` из CMD. Диагностическая версия
сохраняет консоль, чтобы был виден текст ошибки. Журнал самого плеера:
`%LOCALAPPDATA%\AuroraMusicPlayer\player.log`.

Сборка Windows EXE выполняется на Windows. Проверка исходников и инструкции
в Linux не подтверждают работу готового EXE и вид системного заголовка на Windows.

## Автоматическая сборка EXE на GitHub и автообновление в плеере

Workflow [Windows EXE](https://github.com/worstlife123/my-music-player/actions/workflows/windows-build.yml)
запускается при изменении исходника, тестов или сборочного скрипта в `main`,
при отправке тега `v*`, а также вручную через **Run workflow**. Сборка выполняется на Windows x64
с Python 3.13, затем запускаются тесты исходника и сам собранный EXE в режиме
`--smoke-test`. Этот режим использует отдельные временные настройки/данные,
отрисовывает главное окно, затем создаёт мини-плеер и проверяет движение позиции
локального WAV без аудиоустройства. Так ошибки отрисовки меню выявляются до публикации.

Workflow собирает **оба варианта Windows-плеера**:
1. **`AuroraMusicPlayer.exe`** — единый автономный файл (`build_exe.bat single`) + `AuroraMusicPlayer.exe.sha256.txt`
2. **`AuroraMusicPlayer-windows-x64.zip`** — портативная папка `AuroraMusicPlayer` с быстрым холодным стартом + `AuroraMusicPlayer-windows-x64.zip.sha256.txt`

Оба файла сохраняются в артефактах запуска (**AuroraMusicPlayer-windows-x64**, 30 дней) и автоматически публикуются в **GitHub Releases**:
- При коммите в `main`: автоматически создаётся или обновляется релиз по текущей константе `APP_VERSION` в коде (например, `v0.2.0`).
- При отправке тега `v…` (например, `git tag v0.3.0 && git push origin v0.3.0`): публикуется релиз для указанного тега.
- При ручном запуске **Run workflow** можно включить галочку принудительной публикации релиза.

### Кнопка «Обновить» и предупреждение о новой версии внутри плеера

В самом плеере встроена система проверки и установки обновлений с GitHub (`worstlife123/my-music-player`):
- **Автопроверка при запуске и в фоне**: через 3.5 секунды после старта (и далее каждые 4 часа) плеер в фоновом потоке проверяет последний релиз на GitHub Releases и версию `APP_VERSION` в ветке `main`.
- **Предупреждение о новой версии**: если на GitHub появилась более новая версия, сверху под строкой поиска автоматически появляется заметная плашка-предупреждение **«Доступна новая версия v… на GitHub!»** с кнопками **«Скачать и обновить»**, **«Что нового»** и **«Позже»**, а также всплывает тост и системное уведомление в трее.
- **Кнопка «Обновить»**:
  - В левом меню над кнопкой **«Настройки»** (`↻ Обновить · v0.2.0`, а при наличии новой версии подсвечивается зелёным: `⬇ Обновить до v…`).
  - В верхней панели рядом с поиском (появляется при выходе обновления).
  - В меню **«⋯» → «Проверить обновления…»** и в **«Настройки» → «Общие» → «Обновление приложения (GitHub)»**.
- **Обновление в 1 клик**: при нажатии «Скачать и обновить» плеер сам скачивает подходящий пакет для текущего режима запуска (`AuroraMusicPlayer.exe` для single-file EXE, `AuroraMusicPlayer-windows-x64.zip` для папочной сборки или `.py` при запуске из Python), проверяет контрольную сумму SHA-256 / синтаксис и автоматически перезапускает обновлённый плеер.

В CI скрипт `build_exe.bat` не останавливается на `pause`. При локальном запуске
двойным щелчком окно по-прежнему остаётся открытым, чтобы можно было прочесть результат.
